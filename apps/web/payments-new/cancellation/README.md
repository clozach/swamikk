# Stripe monthly cancellation provider adapter

These functions receive an injected Stripe 17.7 client using the installed `2025-02-24.acacia` API. They perform no work at import time. Tests use isolated provider fixtures; no live or test-mode Stripe account is contacted.

`prepareStripeMonthlyCancellation(client, input)` reads the native subscription, its latest invoice, the corresponding charge and complete refund history. The caller supplies a subscription ID obtained from the authenticated tenant/member record, the local payment plan type and expected provider mode. A missing local customer ID is derived from that subscription and frozen after verifying the invoice/charge relationship. Optional membership metadata rejects an actual mismatch while allowing older subscriptions without metadata.

A ready quote contains the actual currency, paid/refunded/remaining amounts in Stripe minor units, test/live mode, current period and internal provider IDs. Only the current period's single subscription invoice qualifies; no older paid invoice is substituted for an unpaid month. The whole remaining current payment is refundable even on the last day. Annual, EMI, metered, scheduled, multi-item, prorated, mixed or otherwise complex invoices require review. An unpaid invoice with a failed charge still attached, an out-of-band payment, a zero-value paid invoice without a charge, customer balance funding, an in-progress refund or incomplete refund history also requires review.

Persist the complete quote on the server. Give the browser a safe projection and its hash. The hash detects a changed quote and tolerates JSON object key reordering; it is not authentication or a signature. Never reconstruct the trusted quote from a browser payload.

`cancelStripeMonthlySubscription(client, quote)` verifies the frozen identity, current period/invoice and subscription scope before immediate cancellation with `invoice_now: false` and `prorate: false`. A previously canceled subscription reconciles as canceled. Provider uncertainty is separate from confirmed cancellation. This adapter does not mutate local membership or access records.

`reconcileStripeMonthlyRefund(client, { quote, operationId, firstAttemptAt, allowCreate })` requires a confirmed canceled subscription. It always reads the frozen invoice and charge, including after the billing period has passed. A matching operation refund returns its native `pending`, `succeeded`, `failed`, `canceled` or `requires_action` state without another create. Another refund or amount/history change after review requires review of a new amount.

The caller must durably claim the first refund attempt before passing `allowCreate: true`, and persist `firstAttemptAt` without resetting it. The first claim must be no more than ten minutes old. All subsequent reconciliation uses `false`, including recovery after a process crash or timeout. Creation uses the exact frozen amount, `kk_cancellation_operation` / `kk_cancellation_quote` metadata, and a stable `kk-cancel-refund:<operationId>` idempotency key. Because Stripe can prune idempotency keys, an uncertain attempt with no matching refund remains uncertain rather than creating again. Failed or canceled refunds also do not automatically start a new operation; a separate reviewed recovery decision is required.

Keep local cancellation/access state separate from refund state: a refund pending, failed or requiring review must not turn a confirmed cancellation back into active membership. Tagged results contain no provider error text or secrets; internal provider IDs remain server-side.

Primary API references: [cancel subscription](https://docs.stripe.com/api/subscriptions/cancel?api-version=2025-02-24.acacia), [create refund](https://docs.stripe.com/api/refunds/create?api-version=2025-02-24.acacia), [idempotent requests](https://docs.stripe.com/api/idempotent_requests), [invoice object](https://docs.stripe.com/api/invoices/object?api-version=2025-02-24.acacia), [charge object](https://docs.stripe.com/api/charges/object?api-version=2025-02-24.acacia).
