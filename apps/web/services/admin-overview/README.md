# Native membership overview and support diagnostics

O01 remains `/dashboard/overview`. `/dashboard/support` opens the same attention and coverage display with source details expanded. Selecting a member uses the shared Member Mimic link and returns to the originating page. There is no separate member-details screen or new editor. The existing role navigation remains available; the site-wide financial and operational projection requires an active, same-tenant `manageSettings` actor. All Mimic cookies, including expired ones, are refused by the GET endpoint. Only `manageUsers` actors receive a linkable, active member ID; display labels are pseudonyms.

`GET /api/admin-overview?days=7|30` returns the app-local `AdminOverview` DTO from `types.ts`. It is an uncached, rate-limited read of existing records. It performs no provider requests, access repair, refunds, mail or content operations. The existing rate-limit bucket is the only write on HTTP reads. There is no new collection to erase, background job, stored snapshot or telemetry collector. Account/tenant cleanup stays with the existing source collections. No contact addresses, feedback text, private practice history, provider IDs, raw errors, card details or sign-in secrets enter the DTO. Diagnostic IDs are stable hashes of tenant/source/native record; the random snapshot ID identifies a particular read, not an end-to-end trace.

## Metric definitions

| Display                                 | Native definition and boundary                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Original paid amount / receipts         | Paid invoices with verified `settlement.at` in the preceding 7 or 30 days, excluding synthetic invoices; grouped by recorded test/live/unknown payment mode and currency. Amounts are major currency units. Missing settlement dates are excluded and recently created undated receipt count is shown. Activity events, checkout attempts and free enrolments are not revenue. No currency conversion, fees, net revenue or unique-customer inference.                             |
| Recorded successful refunds             | Successful amounts from the latest recorded charge evidence for the selected invoices, regardless of refund date. Shared refund freshness projection honors newer exact native operation evidence. Original paid amounts remain unchanged. Observation coverage and the oldest included check time are shown. Missing observations are not zero refunds. If refund or native operation selections fail or reach the record limit, the UI displays the refund total as unavailable. |
| Membership records                      | Native COURSE memberships, including included products, grouped as marked active / pending / other. These count records, not unique people, subscriptions or proven entitlements.                                                                                                                                                                                                                                                                                                  |
| Access records                          | Membership access periods, including historical periods, grouped as active / processing (`freezing` or `prepared`) / ended. This count does not imply every lesson is accessible.                                                                                                                                                                                                                                                                                                  |
| Published products                      | Count of currently published COURSE and DOWNLOAD records; BLOG records are excluded.                                                                                                                                                                                                                                                                                                                                                                                               |
| Payment received; access needs checking | Confirmed receipts at least 60 seconds old, matched to the current native membership session and checked through the authoritative member-access read service. Historical/rejoin receipts, deliberate endings and incomplete source selections are excluded. Checks are deduplicated by member/product and capped at 25. A missing/pending current access result prompts review only. It neither proves payment failure nor authorizes a grant.                                    |
| Other attention                         | Measured access processing; unknown release evidence in a saved prepared/ended cancellation snapshot; unfinished subscription ends; retry/review/overdue signed payment receipts; exact refund/cancellation uncertainty; failed/uncertain/overdue approved content and release changes; failed/uncertain feedback mailbox acceptance. These are records, not unique incidents. A failed or canceled refund is not labeled a successful refund.                                     |

Operational attention includes older unresolved records regardless of the selected payment period. Except the exact published-product count, source selections use the latest 500 matching records by update time; 501 is read to detect truncation. The first 50 attention items are shown, with inferred paid/access review first and older records first within the remainder. A bounded selection can omit older records; the loaded count is not a site-wide total when limited. Source read failure produces explicit unavailable coverage, not a false zero. The snapshot is a series of database reads, not an atomic database-wide transaction; publication, payments and access can change before the next refresh.

Freshness is the latest record in each selection and the current read timestamp. It is not a worker heartbeat or delivery confirmation. The view explicitly does not measure join/OTP funnels, practice playback, cohorts, browser/queue traces, dropped signals, build fingerprints or source maps. Provider acceptance is not inbox delivery. Production collector, access, consent and retention decisions remain separate and are not enabled here.

## Use and verification

1. Sign in as a site settings administrator and open Overview. Check each mode/currency card, its original amount, refund coverage and date; open Transactions for the underlying payment records. The product page also links to Transactions instead of displaying the old duplicate/mixed-currency purchase-activity Sales total.
2. Change Payment period or choose Refresh snapshot. Loading clears the prior result. A failed read says no health result is available; refresh can recover. A late response from an earlier period or identity is discarded.
3. Inspect Needs attention and Coverage and freshness. Empty means only “No items to review in the records checked.” Source failure or limits remain visible. On Support, include the snapshot/diagnostic IDs and observed steps when asking Al for help. Use the existing record's reconciliation workflow; this page never retries a payment, message or content write.
4. With manageUsers, select a linked member, confirm the native Member Mimic profile/banner and exit back to Overview or Support. Settings-only actors see no inaccessible member, product, transaction or content links. A course-only actor sees the explicit site-settings permission state without loading financial data. Entering/expiring Mimic cannot expose a cached administrator snapshot.
5. Compare a native settled payment with test/live and currency variants, a later refund, a stale native/webhook refund result, an old session after rejoin, a processing cancellation and an unknown release-evidence snapshot. The server regressions use isolated Mongo fixtures and verify no access repair occurs on read.

Focused checks: `app/api/admin-overview/__tests__/read.test.ts`, `components/admin-overview/__tests__`, and the shared Member Mimic return-path tests. They cover real REST/tenant/permission boundaries, native financial definitions, source failure and limits, privacy, access inference, client lifecycle and the product Sales regression. Root owns native browser proof, release registration and visuals. This source handoff does not claim rollout.
